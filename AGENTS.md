# Project instructions

## Activity log

- Read `logi.md` at the start of project work so new changes continue the existing record.
- At the end of every substantive development session, append an entry to `logi.md` before finishing.
- Write entries in Estonian. Include the date, related GitHub Issue (if one exists), goal, changes made, checks performed, and outcome or next step.
- Record only work that actually happened. Do not invent dates, tests, or results.
- Keep earlier entries intact; append new entries instead of replacing the log.
- Never put Garmin API keys, bearer tokens, FIT contents, precise routes, or other private training details in the log.

## GitHub Issues

- Use the repository's GitHub Issues to track project work. Link the relevant issue in the log entry and, where practical, in commit messages.
- If a new task has no matching issue, create or propose one before implementation according to the user's authorization and the available GitHub access.
